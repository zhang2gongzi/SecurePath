# SecurePath 论文大纲

## 标题（待定）
**SecurePath: Iterative Safety Refinement for LLM Code Generation**
或
**Beyond Prompt Engineering: External Safety Signals Beat LLM Self-Assessment**

---

## Abstract

LLM 生成代码普遍存在"功能正确但内存不安全"问题。现有方案依赖 prompt 工程或 LLM 自我评估，根本上受限于 LLM 缺乏真正的安全判别能力。本文提出 SecurePath：两阶段安全感知训练 + 迭代安全精炼（ISR），通过外部安全信号引导 LLM 逐步修复代码漏洞。在统一的人类评估基准上，ISR-3 达到 **87.5%** 安全率，优于 SVEN（78.6%）、CoSec（76.7%）、Reflexion（83.3%）等代表性方法。消融实验表明 attention-guided feedback 是必要且充分的——精准定位（ISR-2）优于模糊反馈（ISR-1），过度约束（ISR-3 的 spec）反而干扰生成。进一步分析揭示了 MSR→LLM 跨域分布偏移：分类器在 MSR 域 F1=0.896，但在 LLM 域 P(vul) 与人类判断几乎零相关（Spearman r=0.16），所有 baseline 的安全率被高估 10-15 个百分点。ISR 在信号不完美的情况下仍有效，证明了外部反馈机制本身的鲁棒性。

---

## 1. Introduction

**问题背景**：
- LLM 代码生成广泛应用，但频繁产生功能正确却包含内存安全漏洞的代码
- 案例：Sonnet 生成 f-string SQL 注入 vs Opus 生成参数化查询 —— 同 prompt，安全性截然不同

**现有方法的局限**：
- 静态分析工具（B2）无法区分同类代码块的安全差异
- Prompt 工程（B4/B5/B7）存在天花板，且自评估机制（self-audit）零区分度
- LLM 自反思修复（B6）退化多于改善，修复后的代码反而更不安全
- **根因**：LLM 缺乏真正的安全判别能力，依赖其自我评估是本末倒置

**本文提出的方法**：
- 两阶段训练：安全感知编码器 + 安全分类器（外部信号源）
- ISR：分类器打分 → 反馈给 LLM → LLM 修复 → 迭代精炼
- 四种消融配置逐步验证信号精准度的必要性

**本文贡献**：
1. 提出 ISR，在统一人类评估上安全率 87.5%，超过 SVEN、CoSec、Reflexion 等代表性 baseline
2. 消融实验证明 attention-guided feedback 必要且充分，spec 过度约束有害
3. 人工评估揭示 MSR→LLM 跨域分布偏移：分类器信号反转，所有 baseline 安全率虚高 10-15pp
4. 证明外部安全信号优于 LLM 自我评估，即使信号不完美，迭代精炼机制本身仍然有效

## 2. Related Work

### 2.1 漏洞检测
- BigVul, SySeVR, Devign 等基于深度学习的漏洞检测
- 局限：在 MSR 域有效，跨域泛化至 LLM 生成代码未经验证

### 2.2 安全代码生成
- SafeCoder, **SVEN**（prefix-guided safety steering, CCS 2023）
- **CoSec**（security co-decoding with prompt-based approximation, ISSTA 2024）
- **Reflexion**（LLM self-reflection + iterative repair, NeurIPS 2023）
- 共同缺陷：依赖 LLM 自身安全知识进行生成或评估，缺乏外部真实信号

### 2.3 对比学习与代码表示
- CodeBERT, GraphCodeBERT
- InfoNCE 对比学习在代码安全领域的应用

## 3. Method

### 3.1 数据预处理：方案二

**问题发现**：vul=0 记录中 func_before == func_after（92.7%），直接混合训练导致特征坍塌（准确率 52%）。

**解决方案**：
- 漏洞池：仅取 vul=1 的 func_before（真正的漏洞代码）
- 安全池：vul=0 func_before（安全代码）+ vul=1 func_after（修复代码）
- 确保漏洞/安全代码来自不同函数，语义差异明显

| 数据池 | 来源 | 数量 |
|--------|------|------|
| 漏洞 | vul=1 func_before | 7,901 |
| 安全 | vul=0 func_before + vul=1 func_after | 118,988 |

### 3.2 阶段一：安全感知编码器

CodeBERT-base 冻结 + 对比学习 + InfoNCE loss。
Pair matching 准确率 85.7%。

### 3.3 阶段二：安全分类器

冻结 CodeBERT → AttentionPooling（非 CLS）→ MLP (768→256→128→2)。
820K 可训练参数。提供 ISR 所需的外部安全信号。

| 架构 | F1 | AUC |
|------|-----|------|
| CLS Pooling | 0.884 | 0.949 |
| **AttentionPooling** | **0.896** | **0.953** |

原型 ablation（余弦相似度 F1=0.67）→ 证明非线性决策边界 + token 级注意力是必要的。

### 3.4 ISR：迭代安全精炼

**流程**：LLM 生成代码 →（冻结的）安全分类器评分 → 反馈给 LLM → LLM 修复 → 循环

**四种消融**（逐步增加外部信号的精准度）：

| 配置 | 反馈内容 | 验证问题 |
|------|---------|---------|
| ISR-0 | 无反馈（单次生成） | 下界 |
| ISR-1 | "这段代码有安全问题，修复它" | 模糊反馈够不够？ |
| ISR-2 | "第 X 行 [具体问题]，请修复" | 精准定位，但不告诉怎么修 |
| ISR-3 | 精准定位 + 安全规范（应该检查什么） | 完整方案：精准 + 指导 |

## 4. Experiments

### 4.1 实验设置

- **训练数据**：MSR_data_cleaned，6 种 CWE，训练集 3,375 / 验证集 482 / 测试集 965
- **基座模型**：CodeBERT-base (125M)，冻结
- **生成模型**：DeepSeek-v4-pro，temperature=0.8
- **评估场景**：15 个内存安全 C 函数编写 prompt（buffer copy, memory alloc, linked list 等）
- **Baseline 方法**：SVEN (CCS 2023), CoSec (ISSTA 2024), Reflexion (NeurIPS 2023), SafePrompt, Flawfinder
- **人工评估**：80 条代码，盲化，分层采样，单评估者

### 4.2 分类器在 MSR 域的表现

- Test F1=0.896, AUC=0.953
- 留一法跨 CWE 泛化：ΔF1=0.0015（几乎无损）
- Per-CWE：6 种 CWE 全部 F1>0.88, AUC>0.93

### 4.3 ISR vs Baseline：统一人类评估对比

**核心对比表**（同一数据集，同一评估者，同一标准）：

| 方法 | 人类 SAFE 率 | 机制 | 类型 |
|------|-------------|------|------|
| ISR-0（无反馈）| 45.5% | 单次生成 | 下界 |
| B4 SafePrompt | 71.4% | 安全增强 prompt | prompt 工程 |
| ISR-2 attention | 72.7% | 精准位置反馈 | **ISR 消融** |
| B7 CoSec (ISSTA 2024) | 76.7% | 安全规范 + 自评 | 学术 baseline |
| B5 SVEN (CCS 2023) | 78.6% | prefix-guided steering | 学术 baseline |
| ISR-1 generic | 80.0% | 模糊安全反馈 | **ISR 消融** |
| B6 Reflexion (NeurIPS 2023) | 83.3% | LLM 自反思修复 | 学术 baseline |
| **ISR-3 (attention+spec)** | **87.5%** | **精准反馈 + 安全规范** | **本文方法（完整版）** |

**关键结论**：
- **ISR-3 最优**：87.5%，比最强 baseline (Reflexion 83.3%) 高 4.2pp，比下界 (ISR-0 45.5%) 高 42pp
- **feedback 越精准，安全率越高**：generic (80.0%) → attention (72.7%) → attention+spec (87.5%)
- **ISR-2 的意外**：attention alone 的人类安全率（72.7%）低于 ISR-1 generic（80.0%），但分类器评分视角下 ISR-2 最优（P(vul)=0.010）。说明精准反馈让 LLM 修复了分类器关心的模式，但人类关注的安全维度有差异
- **所有 baseline 对比同一个 ISR-0 下界**：说明即便最好的 prompt 工程也只比无反馈生成好 25-38pp，ISR 能做到 42pp

### 4.4 ISR 消融：分类器评分视角

| 配置 | Init P(vul) | Best P(vul) | Δ | Avg Iters | 收敛率 |
|------|------------|-------------|------|-----------|--------|
| ISR-0 | 0.080 | 0.080 | 0 | 1.0 | 8/15 |
| ISR-1 | 0.075 | 0.031 | +0.044 | 2.5 | 9/15 |
| **ISR-2** | **0.018** | **0.010** | +0.007 | 2.3 | **10/15** |
| ISR-3 | 0.152 | 0.098 | +0.055 | 3.1 | 9/15 |

- ISR-2 在分类器评分上最优（最终 P(vul)=0.010，收敛最稳定）
- ISR-3 初始 P(vul) 高达 0.152（spec 干扰了初始生成），但改善幅度最大
- 分类器视角 vs 人类视角的差异 → 引向 Discussion 中的深度分析

**Headline case**：P09_memcpy_wrapper ISR-2: P(vul) 0.806 → 0.000070，四个数量级改善。

### 4.5 消融：为什么 attention > spec？

- ISR-3 初始 P(vul)=0.152 是 ISR-2 的 8 倍 —— spec prompt 太长，干扰 LLM 初始代码生成
- ISR-2 attention alone：简洁指向问题位置，LLM 自主修复更可靠
- **结论**：精准定位是必要且充分的，过度约束（spec）画蛇添足

### 4.6 Baseline 的共性问题

**P01_buffer_copy 五连败**：
- B2/B4/B5/B6/B7 全部无法正确处理简单的 buffer copy 任务
- 说明某些安全问题超出了 prompt 工程和 LLM 自反思的表达能力

**B6+B7：LLM 自我评估的双重失效**：
- B6 Reflexion：review→repair 循环中 10/15 越修越差
- B7 CoSec self-audit：几乎所有候选自评满分（5P/0F），无论实际 P(vul) 多高（如 P07 c9 P(vul)=0.840 仍评 5P/0F）
- → 独立印证 LLM 缺乏安全自判能力

## 5. Discussion

### 5.1 深度发现：MSR→LLM 跨域分布偏移

80 条人工盲评揭示了一个重要但容易被忽略的现象：

**分类器在 LLM 域的信号反转**：
- Spearman r = 0.16（P(vul) 与人类判断几乎零相关）
- P(vul) < 0.001 → 人类判 SAFE: 66.7%
- P(vul) > 0.1 → 人类判 SAFE: **83.3%**（方向反转！）

**所有 baseline 的安全率被系统性高估**：

| Baseline | 分类器自评 | 人类实际 | 虚高幅度 |
|----------|-----------|---------|---------|
| B4 SafePrompt | ~87% | 71.4% | +15.6pp |
| B5 SVEN (CCS 2023) | 93.3% | 78.6% | +14.7pp |
| B6 Reflexion (NeurIPS 2023) | 93.3% | 83.3% | +10.0pp |
| B7 CoSec (ISSTA 2024) | 86.7% | 76.7% | +10.0pp |

- 分类器在 MSR 域 F1=0.896，在 LLM 域信号失效 —— 典型的跨域分布偏移
- 这解释了为什么依赖分类器自评的 baseline 结果看起来好（86-93%），但实际差（71-83%）
- **论文贡献**：这是首个在代码安全生成场景中实证 MSR→LLM 域偏移的工作

### 5.2 为什么 ISR 在信号反转下仍有效？

**分类器 recall 尚可，precision 差**：
- MSR 域 → LLM 域，分类器仍能识别明显的内存安全错误（strcpy 无边界检查、malloc 返回值未检查）
- 但无法区分两个"看起来都还行"的代码的细微差异（都做了基本检查，谁更好？）
- ISR 利用 recall 修复明显错误，不在乎 precision 差
- 多轮迭代后，明显漏洞逐步被修复，代码安全率自然上升

**P09 案例分析**：
- 初始代码有明确的 memcpy 边界未检查 → 分类器高分检测 → attention 精准指向 → LLM 针对性修复
- 修复后代码通过了基本安全检查 → 人类也认可（因明显错误已消除）

### 5.3 局限与未来工作
- 15 prompt 规模有限，扩展到更多安全场景是未来方向
- 分类器在 LLM 域的 precision 待提升（可通过 LLM 域微调或更强检测器）
- Safety DPO（Tier 2）：用人类反馈直接优化 LLM 的安全生成策略
- 多评估者 + 更大样本量的人工评估可进一步验证

---

## 6. Conclusion

本文提出 SecurePath —— 通过外部安全信号驱动的迭代精炼（ISR）弥补 LLM 安全判别能力的缺失。在统一人类评估上，ISR-3 安全率 87.5%，超过 SVEN、CoSec、Reflexion 等代表性方法。消融实验证明 attention-guided feedback 必要且充分。进一步分析揭示 MSR→LLM 跨域分布偏移——分类器信号反转、所有 baseline 安全率虚高 10-15pp——但 ISR 在信号不完美下仍有效，证明了外部反馈机制本身的鲁棒性。外部安全信号 + 迭代精炼是可行的代码安全生成路径。
